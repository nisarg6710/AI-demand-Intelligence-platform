# Milestone 12 — MLflow Experiment Tracking

## Overview

This milestone introduces **MLflow-based experiment tracking** to the AI Demand Intelligence Platform.

The forecasting pipeline previously stored experiment results in MySQL. MLflow is now integrated alongside the existing database layer to provide dedicated MLOps experiment tracking.

The implementation tracks:

- Model parameters
- Evaluation metrics
- Experiment metadata
- Run tags
- Forecast visualizations
- Experiment history

---

## Objectives

The objectives of this milestone were:

1. Introduce MLflow into the forecasting pipeline.
2. Create a reusable MLflow tracking utility.
3. Track classical forecasting experiments.
4. Log model parameters and evaluation metrics.
5. Store forecast visualizations as MLflow artifacts.
6. Maintain MySQL as the application's operational forecasting database.
7. Provide a local MLflow UI for experiment analysis.

MLflow complements the existing MySQL experiment tracking rather than replacing it.

MLflow Integration

A reusable tracking wrapper was created at:

src/mlops/mlflow_tracking.py
MLflowTracker

The tracker provides methods for:

start_run()
end_run()
log_params()
log_metrics()
log_tags()
log_artifact()
log_artifacts()
log_model()
get_active_run_id()

The class also performs basic value cleaning before sending parameters and metrics to MLflow.

Tracking Backend

The local MLflow tracking backend uses SQLite:

sqlite:///mlflow.db

The MLflow database is intentionally excluded from Git.

The following files/directories are ignored:

# MLflow
mlflow.db
mlflow.db-shm
mlflow.db-wal
mlruns/
mlartifacts/
Experiment

The forecasting experiments are stored under:

AI-Demand-Intelligence-Forecasting

Tags

project

model_family
model_name

Example:

project: AI-Demand-Intelligence-Platform
stage: forecasting
model_family: classical
model_name: ProphetModel
Artifacts

Forecast visualizations are generated by the forecasting pipeline and logged to MLflow.

Example:

forecasts/
└── ProphetModel_forecast.png

The visualization contains:

Training data
Actual test data
Model predictions

This allows experiments to be evaluated using both numerical metrics and visual forecast behavior.

MLflow UI

The local MLflow tracking server can be started with:

python -m mlflow ui `
    --backend-store-uri sqlite:///mlflow.db `
    --host 127.0.0.1 `
    --port 5000 `
    --workers 1

The UI is available at:

http://127.0.0.1:5000

Important Design Decision

MLflow does not replace the existing MySQL forecasting infrastructure.

MySQL remains responsible for:
Forecast predictions
Application-facing data
Forecast experiment records
Analytics data
MLflow is responsible for:
Experiment tracking
Run metadata
Parameters
Metrics
Tags
Artifacts
MLOps experiment history

This separation allows the application layer and MLOps layer to evolve independently.
